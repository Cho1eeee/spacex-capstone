Introduction: Background and Problem Statement

Background. SpaceX has disrupted the economics of space launch through booster reusability. The Falcon 9 first stage can return to land or to a droneship and fly again — the fundamental reason its pricing is far below traditional expendable rockets.

Problem statement. If first-stage recovery success could be predicted from launch parameters (payload mass, orbit type, launch site, booster state, etc.), it would:

  • Inform booster-reuse scheduling and insurance pricing;
  • Identify the key factors driving successful recovery.

Data science framing. Model it as a binary classification problem:

Class 1 = successful landing  |  Class 0 = failed landing

Data sources: SpaceX REST API v4 (launches, rockets, launchpads, payloads endpoints), supplemented by web scraping of public launch lists for cross-validation.

Time span: all 90 Falcon 9 launches from 2010–2020 (covering the full landing-attempt era).

Data Wrangling Methods

1. Label engineering

  • Outcome (e.g. True ASDS / False Ocean / None None) → binary label Class (1 success / 0 failure), plus a LandingAttempt flag.

2. Missing-value handling

  • Missing payload mass → imputed with the mean of the same booster model; missing LandingPad → "Unknown".

3. Types and dates

  • date_utc → datetime, deriving a Year feature for trend analysis.

4. Feature encoding

  • One-hot encoding of Orbit / LaunchSite / LandingPad / Serial, producing an 82-dimensional feature matrix.
  • Physical features retained: PayloadMass, Flights (reuse count), GridFins, Reused, Legs, Block, ReusedCount.

Outputs:

  • dataset_part_2.csv: labeled cleaned data (90×20)
  • dataset_part_3.csv: ML feature matrix (90×82)

Exploratory Analysis with SQL (SQLite)

Cleaned data loaded into SQLite (SPACEXTBL); 8 query groups executed covering launch sites, payloads, success rates, rankings, and time:

  • Sites: DISTINCT LaunchSite → 3 sites
  • Payloads: total mass for 0–10000 kg; details for 4000–6000 kg; average payload per orbit
  • Success-rate ranking: KSC LC-39A 77.3% ＞ VAFB SLC-4E 76.9% ＞ CCAFS SLC-40 60.0%
  • Booster ranking: B1049 6/6 landings successful, B1051 5/5, B1059 4/4
  • Time analysis: 18 launches in 2017 at 83.3% success; 19 launches in 2020 at 84.2%
SELECT LaunchSite,
  COUNT(*) AS Attempts,
  SUM(Class) AS Successes,
  ROUND(100.0*SUM(Class)/COUNT(*),1)
    AS SuccessRate
FROM SPACEXTBL
GROUP BY LaunchSite
ORDER BY SuccessRate DESC;
→ KSC LC 39A | 22 | 17 | 77.3
→ VAFB SLC 4E | 13 | 10 | 76.9
→ CCAFS SLC 40 | 55 | 33 | 60.0

Conclusions, Best-Model Explanation and Novel Insights

Best-model explanation. The Decision Tree with max_depth=2 wins at 88.9% test accuracy, reaching high precision with only 2–3 key features — recovery outcomes are dominated by a few strong predictors (booster version/reuse state, orbit, launch site). The tree is interpretable and auditable, well suited to safety-related decisions.

Conclusions.

  • First-stage recovery success is predictable; a lightweight model reaches ~89% accuracy;
  • KSC LC-39A and VAFB success rates are significantly higher than CCAFS SLC-40 (which hosted the early experimental launches);
  • The success-rate improvement is driven by technical iteration (>84% in the Block 5 era), not by lighter payloads.

Novel / creative insights.

  • Doubly cross-validated data pipeline: automatic fallback when the primary API source fails + independent live-API verification — more robust than a single source;
  • Quantified geography: Folium quantifies site proximity to coastline/railway/cities, explaining the recovery economics of site selection;
  • Interpretability first: a shallow decision tree outperforms complex models — "less is more" for this problem;
  • Future work: incremental updates from the live SpaceX API; weather and downrange-distance features; SHAP-based feature attribution.
